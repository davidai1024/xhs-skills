# 示例：让AI在Mac搭建快捷指令

目标：面向AI/Mac进阶用户，分享一次由AI实际操作桌面软件、搭建并测试文件夹自动化的案例。

建议内容结构：已选封面 → Computer Use及系统权限 → TXT转MD场景请求 → ZIP解压场景请求 → 实测验收。仅为该案例的合理页序，不是所有教程必须五张。

自然语言请求应描述：何时触发、监听范围、输出位置、原件如何处理、冲突如何处理、要求直接搭建并测试。不要把教程写成用户逐个拖拽动作节点的手册，因为案例核心是“描述场景，让AI操作”。

TXT示例：把新TXT放入自己的目标文件夹，生成同名MD，保留内容；保存成功后原件移到废纸篓；同名MD保留源文件不覆盖。
ZIP示例：监听自己的仓库及需要的子目录，解压到指定同名目录，保留ZIP和内部目录结构。冲突规则需明确要求并测试，不能从旧截图推断。

对于当前产品，核对官方Computer Use文档；账号、地区、桌面端和操作系统版本可能影响入口与可用性。权限路径用准确示意，真实快捷指令画面才标“截图”。在读者本机搭建前先确认macOS支持对应文件夹触发能力。

本案例用户最终选定的收尾为：标题“搭建完成。再做一次实测。”＋单张真实流程截图＋三项验收点（自动触发、结果正确、原件与冲突）＋一句测试请求。它是在教读者验收，不是假装展示运行结果；后续双结果截图及等高双卡尝试被用户否定，不作为本案例默认版式。只有类似需求且用户未另选时参考，不推广为所有教程的固定收尾。
