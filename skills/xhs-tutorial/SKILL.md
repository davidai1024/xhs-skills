# 小红书·图文介绍

先确定整篇的主要观看目的，把已确认的素材写成内容稿，再组织图文分镜并制作 PNG。本技能沿用历史名称，但多页图文不一律是操作教程。支持制作、修改、只评审三种请求；只评审时不擅自改图。用户当前选择的受众、配色、页序和封面优先。

## 延续已选方案

先区分用户要求“评审”“局部修改”或“整套重做”。只评审时不改图；获准优化后，修正与发现直接相关的问题。已选版式、账号落款与配色不因模型的主观审美判断而被重做；视觉尝试另存备选，用户回选旧版时精确恢复并合入当前整套。

## 先确定内容与证据

从对话、成品和真实截图确定目标读者、本篇主要收获及可用材料；读取 [按观看目的选择讲法](references/content-modes.md)。主讲法可以是展示、探索、经历、解释、评价或教学，允许混合。只有任务教学才按需补齐前提、入口、动作、结果和验收，不凭工具或Skill字样自动判成教程。受众不明确但可合理推断时先声明假设继续，不要求填表。AI/Mac 选题不能自动推定读者是新手。

区分三件事：作者已经实测的结果、读者可复用的操作请求、尚需在读者环境验证的条件。不要把一句提示词包装成对所有版本和账号均有效的保证。涉及当前产品权限、入口和支持范围时核对官方资料，必要时使用对应产品文档技能。

## 先写内容，再编排和生图

读取 [内容写作与分镜](references/content-writing.md)，按本篇素材选择讲法；其中写作顺序与检查方法基于50期影视飓风字幕的逐期研究，默认落实到内容稿，不只添加口语词。需要追溯时再读其中链接的逐期记录。先确定本篇要讲清的具体事情和工作标题，再写一份可以连续阅读的内容稿；不要先定几页版式，再用几句摘要填满。文稿可以是叙述或确实适合本篇的清单，不强迫所有主题套同一故事结构。

内容结构与表达同时检查。写稿及改稿时读取 [表达方式与文字节奏](references/expression.md)：本账号当前采用从影视飓风内容研究中提炼的带看、解释和坦率评价方式，落实到说话关系、程度用词、主语与动作、条件句、句末信息及长短变化；用户另定口吻时从新要求。完整稿写出后再做一遍表达修订，不把“讲清楚”当成口吻已经到位，也不靠堆口头禅冒充相似。图文删去现场冗余，保留有作用的指认、改述与判断。

出图前检查：对象是否清楚，例子是否解释了意思，原因与下一步是否接得上，操作有没有输入和产物，数字和效果有没有依据。“找到看点、兑现期待、提高效率”一类概括只有落到本篇的具体事实才有用；不靠禁词或加口语词伪装人味。发现抽象空转，先补例子或重写文稿，不用漂亮排版掩盖。

文稿写清后再按意思分页，确定每页留下的文字与需要的证据画面。标题、截图和正文共同说明一个问题；不能为短标题删掉理解所必需的对象、原因或条件。单页装不下时先分开意思，不机械缩小文字或砍掉例子。

已授权制作整套图文时，内部完成内容检查后继续制作，不新增例行审批；用户只要求研究或改稿时交付文稿及必要分镜，不提前做图。只修一张图的字号或位置且文案未变时，不重写整篇；若改动内容承诺或步骤，则复查受影响文稿。

## 编排与绘制

- 已选封面保留；用户要求统一换风格时另存新版本。需要制作封面时可用 `$xhs-cover`，复用其内容结构，当前用户风格选择优先于旧模板配色和字体。
- 避免整套都套“大标题＋大灰卡”，版面跟随主讲法。教学案例可让准备页突出入口、主场景保留完整请求、追加场景缩短重复，收尾按需要选择实测产物或验收指南。展示、纪实和讨论不自动采用这套步骤顺序。优先保留用户已选定的收尾结构；按页面目的选择验收指南或成果展示，不把真实性要求误变成强制展示两张输出截图。标题尽量简短；配置截图不充当实际输出的证据。
- 每页交付与主讲法相关的一份新信息、观察、情绪、判断或动作。教学可按任务步骤，解释沿因果，经历沿真实变化，展示沿画面差别，互动沿实际回合。页数由内容决定，不固定为四页；不要求每页都有提示词或验收。
- 精简图面解释：不默认添加“效果示意”“操作路径示意”“换个场景也一样”等页脚小字，或重复主流程的总结。素材说明、版本条件优先放附带说明；会影响读者执行的前提融入对应步骤。图中只保留帮助当前动作的必要文字，不靠多加解释填满留白。
- 尽早交付封面承诺的具体内容。结尾按主要观看目的收束，作品、感受、判断、未解问题或下一步均可能成立；需要读者执行时再给可采取的动作。正文页标题说明当前有意思或有用的东西，少用空词。
- 软件操作教程优先真实界面局部和关系示意。提示词型教程可用“输入 → 输出”的短流程加可复用请求，不必逐个解释软件动作节点。
- 需要交付操作型提示词时，包含实际操作请求、输入范围、输出要求和验收；涉及原件处理或覆盖时补充规则。路径参数明确标注为读者需替换或让AI确认的内容。
- 阅读 [layout.md](references/layout.md)，使用 [apple-editorial.css](assets/apple-editorial.css) 作为可改的原生排版起点。账号落款默认使用随技能保存的真实头像与小号文字，尺寸和底部留白见layout。默认采用本用户指定的苹果风：白、近黑、浅灰，蓝色只用于少量操作提示；不沿用旧版紫色大标题。用户另选风格时覆盖此默认。
- 用 HTML/CSS 或设计软件精确排字。真实截图不拉伸、不重绘；流程图、设置路径示意和实际截图分别说明，不把示意伪装成运行证据。不要为做教程修改原工具。仅为出版取证而新增的实测应使用隔离临时样例，核验后移出用户业务目录；已有足够证据或页面仅教验收时，无需重复实测。

## 必须完成的评审与交付

制作后或用户只要求评审时，阅读 [review.md](references/review.md)，分别检查文稿是否能读懂，以及最终真实图片的逐页和整套阅读。记录发现的问题、影响和最多三项优先改动；已授权制作时直接修正明显问题并复查。没有真实读者测试或发布数据时，只能给编辑判断，不能报伪造的分数、盲测反馈或预估点击率。

导出后检查原图和360px预览；180px模拟双列主要评封面，不要求正文小字在双列逐字可读。记录实际字体、尺寸、布局与溢出检查结果。确认所有可见段落都在安全区，不能只检查DOM宽度。

整套制作任务保留连续内容稿与分页脚本，再交付逐页 PNG、整套预览和 ZIP；有复制价值的提示词另附文本。核验 PNG 尺寸、页序、ZIP成员及内容一致，旧版保留。最终回复给预览、下载和简短评审结论。不要自动发布。

主题适配示例见 [example-obsidian.md](references/example-obsidian.md)，仅在制作类似AI电脑操作教程时读取；不把示例路径、版本或本机成功结果当成新任务事实。
