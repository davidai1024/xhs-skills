# 已实测浏览器路径与边界

2026-11-12 在已登录的小红书 Chrome 网页实测。页面和字段会变化，每次先观察当前状态再使用选择器，不能照抄索引、会话 token 或请求 ID。

## 真实话题候选

创作者端正文输入 `#检索词` 后的话题选择器可返回名称与浏览量。对应候选元素的 `data-impression` DOM 属性在本次包含 `tagTarget.value.tagId`。这是候选本身的公开身份字段，不读取 cookie、请求凭证或与任务无关的埋点数据。

本次观察到候选的 DOM 为 `.item`，名称 `.name`，浏览量 `.num`。这些仅是排查线索；先检查当前元素再提取。等待候选更新且与当前查询一致，不能把上一轮列表记到新查询名下。

优先使用专用测试编辑页。若只能在已有编辑页查询，先记录原有正文与选择状态，结束时准确恢复，不点击候选插入、不发布、不点击暂存离开。`fill('')` 在本次未实际清空 contenteditable；必须检查正文 DOM 和字数，必要时仅在正文获得焦点后选择全部并删除临时查询。已有正文非空时不得误删用户内容。

## 关键词抽样与按 ID 核验

1. 在小红书搜索相关词，使用真实筛选菜单选择“最新”或“最多点赞”，收起菜单再打开样本。记录选择的排序，不称作话题自身的最新/最热榜。
2. 打开笔记之前，若当前浏览器工具明确提供 CDP 能力，阅读其文档后临时开启 `Network.enable`，保存 `Network.responseReceived` 事件游标。
3. 用正常页面操作打开已观察到的笔记链接。仅定位当前笔记的 `/api/sns/web/v1/feed` 返回。用支持的 `Network.getResponseBody` 读取这条已发生的响应；不重放签名请求，不注入脚本调用内部 API，不遍历 cookie/存储。
4. 本次响应结构为 `data.items[].note_card`，包含 `note_id/title/desc/tag_list/time/last_update_time/interact_info`。`tag_list` 含 `id/name/type`。只接收 `note_id` 与当前打开笔记一致的对象，不能拿后台返回的其他卡片代替。
5. 捕获到 `responseReceived` 仍可能未下载完成。等待页面详情实际加载，按工具文档继续读取游标或重试读取同一个响应体；设置有界超时，失败记为失败。没有新响应可能是缓存，不能沿用上一篇数据。
6. 对照页面标题、可见话题和互动数核验返回。保存必要的公开字段；不保存完整网络日志、cookie、请求头、带会话参数的 URL、二维码或个人资料。笔记链接保存为 `https://www.xiaohongshu.com/explore/{note_id}`，注明之后访问可能需要重新搜索或登录。
7. 完成后关闭本次临时启用的 Network 监听，遵守浏览器工具的收尾要求。

不能使用响应读取能力时，可以仅以 DOM 标签名称作弱证据，但必须标记“名称核验，ID 未核验”。若用户要求严格按 ID，报告缺口，不将弱证据升级。

## 本次验证揭示的坑

- 搜“AI编程”返回的笔记不一定关联 `AI编程` 话题；本次 5 篇人工选择样本中，2 篇匹配目标 ID，3 篇不匹配。它不是总体命中率估计。
- “Codex”和“codex”在本次候选/笔记中出现了不同 ID。不能只做大小写归一化合并。
- 搜索卡片展示“1小时前”的样本，真实创建时间与最后更新时间不同。最新不等于新发。
- 按 `/page/topics/{id}` 访问的一次网页尝试未能提供话题详情，不能假定该路径在桌面端可用。
- 页面中可能有同名隐藏/极低透明度辅助元素。先查看 DOM/截图识别实际控件，避免点到辅助元素；不要通过随意修改页面来解决。
