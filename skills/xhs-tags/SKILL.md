# 小红书·标签

输出可核查的真实候选及其适配理由。默认优先选择**与内容相关、有真实浏览量数据、在相关候选中热度较高**的话题，交付前主动完成筛选，不等用户逐轮提醒补数据、比较热度或核对同名话题。AI 生成的词仅用于检索，不能凭生成结果认定话题存在或有热度。

## 获取证据

从用户的笔记、图片和目标读者提取少量检索词。信息足够时直接查；缺少素材会影响推荐时先做可独立完成的查询，再补问。

优先使用当前环境已连接、能提供真实返回的渠道。浏览器操作先阅读工具提供的当前文档；具体已实测的浏览器流程见 [references/browser-workflow.md](references/browser-workflow.md)。不把文档样例、搜索摘要或供应商宣传当作本次实测。

- 话题候选：保存名称、真实 ID、浏览量原文、查询时间和来源。没有话题 ID 的字符串只列为未核实候选。
- 笔记样本：保存笔记 ID、链接、标题、必要的正文摘要、话题 ID 列表、发布/更新时间及可见互动数。只收集任务需要的公开字段。
- 优先按话题 ID 获取最新/热门笔记；不可用时，允许通过关键词搜索的“最新”“最多点赞”等排序找样本，再检查每篇笔记的真实话题 ID。后一条是搜索抽样，不能称为完整话题榜单。
- 使用实际存在的浏览器接口，或明确配置的供应商 API。密钥只能从相应环境变量/安全配置读取，不写入 skill、报告或日志。没有配置时不虚构接口已打通；不擅自注册、购买或向第三方传递小红书登录凭证。

## 入选条件与比较顺序

- **相关性先过关。** 根据本篇内容和目标读者，先看话题介绍或按真实 ID 核验的相关笔记；不为追热度加入无关话题。笔记里出现某个关键词，不等于实际关联了该话题。
- **真实数据是入选条件。** 推荐项必须同时具备真实话题 ID、平台可见浏览量原文、采集时间和来源。浏览量缺失、未返回或无法核实的，即使有相关笔记使用，也只能列为待查，不能放入推荐标签或发布正文。先尝试补查，仍取不到就换用证据完整的相关候选，或少推荐几项。
- **有数据后还要比较热度。** 不因某个话题“有数字”就入选。对照内容核心词、相关上位词及名称变体，优先选择主题相符且浏览量较高的候选；不能只查到一个窄话题就结束。整体兼顾覆盖面与本篇核心主题，较小但不可替代的垂直话题可以保留，并说明理由；不把整组标签都交成低热度长尾词。没有必要凑固定数量，也不设脱离内容的统一浏览量门槛。
- **同名、大小写及变体逐 ID 比较。** 保留平台显示的准确名称，分别查询容易混淆的候选，把各自 ID、浏览量及适配样本并排核对。样本使用的 ID 必须与推荐项一致，不能用另一个同名 ID 的热度补足证据，也不能把大小写统一后合并浏览量。对热度更高但尚无适配样本的变体，继续核验相关性再决定，不机械只选第一个返回项。
- **完成比较再定稿。** 推荐表、复制标签、发布正文和证据文件必须指向同一组名称与 ID；明确淘汰无数据、无关以及被更合适高热度候选替代的话题。用户锁定的话题保留其选择，发现证据不足时单独提示，不默默冒充已核验。

## 核验与筛选

1. **身份按 ID 判断。** 笔记标题命中关键词、正文出现同名字符串，都不能证明关联了该话题。名称相同或仅大小写不同但 ID 不同，保留为独立话题并提示歧义，不擅自合并其热度。
2. **指标保持原义。** 浏览量不是搜索量，不知道统计窗口就留空。“万/亿”等显示值保留原文与约数标记。空白、“赞”、未返回不是零；数字只从指标字段解析，不能取话题名称里的数字。
3. **发布与更新分开。** “最新”搜索结果可能是最近更新的旧笔记。按发布时间判断样本新旧，保留更新时间；没有两个可比快照，不计算增长率。
4. **先相关性，后热度。** 阅读话题介绍或已核验的代表笔记，判断真实主题、受众与用户内容是否一致。排除同名异义、活动资格不符、内容无法兑现的候选。只有标题/没有足够样本时，降低判断强度。
5. **不把抽样当全量。** 记录查询、排序、抽样方式、样本数量和 ID 核验结果。样本没有命中，只能说明本次未找到；不能断言话题不活跃。高赞样本关联某 tag 不能证明 tag 导致高赞。

## 输出

先交付可直接复制的推荐标签，再给必要的证据：准确名称与 ID、原始浏览量、采集时间、代表笔记链接、选择与排除理由。存在同名不同 ID 时说明本次应选哪一项，不能只给一个容易选错的名称。数据不足时明确输出“已核实存在，但暂无充分依据推荐”，放在待查区，不混入可复制的推荐标签。

区分三种状态：已核实存在 / 已有适配样本 / 发布效果已验证。第三种只能在有相应效果证据时使用。不套固定标签配额，不承诺流量。

需要保存结果时使用 JSON 证据文件。可用 `scripts/build_evidence.py --candidates <JSON> --samples <JSON> --output <JSON>` 整理数据并按真实话题 ID 连接样本；它不联网、不采集数据，也不自动给出流量评分。样本格式见该脚本的模块说明。

## 交付前自查

逐项检查最终推荐，而不只检查采集是否成功：

1. 每个推荐项都与本篇内容相符，有真实 ID、浏览量、采集时间和来源；没有缺数据项混进正文。
2. 已比较相关的宽主题与垂直主题，存在更合适、更高热度的候选时已考虑替换；若保留较小话题，有具体的内容理由。
3. 同名、大小写及变体没有串用 ID 或浏览量，适配样本与推荐话题按 ID 对应；不能用“搜到了相关笔记”替代关联核验。
4. 复制区、正文、推荐表及保存文件一致；历史淘汰项没有继续作为当前推荐流出。

任一项不满足，先补查或调整推荐再交付。若访问限制导致无法完成，明确说明缺口，不能把有限核验说成已完成筛选，也不把浏览量高说成发布效果保证。
