# 小红书·封面

这是一套内容封面系统，不是固定产品广告模板。继承参考的浅底、大字、留白和主体展示，同时明确各区域的信息职责。用户当前要求覆盖参考中的旧文案、标识与排版。保留参考原文件不变。

## 延续已选方案

本用户默认Apple风，优先沿用本次明确选定的标题、素材、构图及头像落款。只评审时先给判断，不改文件；获准优化时围绕具体问题局部修正，不因模型偏好更换已选方向。

封面与教程是两个交付范围：本技能负责封面，后续正文轮播由 `$xhs-tutorial` 处理，不把封面的固定坐标套给所有正文页。标题与素材标注不能把配置页面说成运行结果。

## 信息结构：先确定写什么，再决定怎么排

每张封面先在内部确定五个字段：内容类型、主标题、副标题、主体素材、账号落款；系列名与期数为可选字段。已有选题与素材足够时直接完成，不要求用户填写表单。

1. **顶部类型位：回答“这是什么内容”。** 默认显示内容类别，不把产品品牌当成唯一顶部标签。位置可左上或顶部居中，随版式选择。类型示例为「小红书小工具」「Agent Skill」「知识分享」「产品分享」「工作流教程」。依实际内容选一个，不能把几个类别并排堆放。
2. **主标题：回答“它能做什么／为什么看”。** 用具体场景、动作、结果或观点，通常两行，必要时三行。产品名可以出现在标题中或主体素材内，不必重复占据顶部类型位。不得虚构免费、无需下载、性能、效果或爆款保证。
3. **副标题：补充一个主标题未说清的信息。** 可是使用方式、差异点、范围或一句解释；通常一行，必要时省略。不要用一排功能标签重复标题。
4. **主体展示：让读者看见内容本身。** 优先真实软件截图、相机界面、文档局部、照片结果或书籍网格；不是默认生成摆拍商品。主体素材随选题变化，不能每次都套“左边产品、右边相纸”的广告构图。
5. **底部落款：回答“这是谁的内容”。** 默认使用随附真实头像＋「关注职场咸鱼」，整组置于主体下方并居中；文字22px、头像32px、间隔12px，y1368，距底40px。用户提供新账号或新文案时替换。不要照搬参考中的「职场懒人」「职场懒人姐」等作者名。系列可增加一行「系列名 · 第 N 篇」，仅在期数已知时写入。

类型按发布内容判断，不按实现技术猜测：用户在小红书发布可使用的小工具，本次类型就是「小红书小工具」；即使用 AI 做成，也不因此归为 Agent Skill。分享可复用的技能文件或技能包才归为 Skill；解释概念归为知识分享；介绍或体验现成产品归为产品分享；讲操作流程归为工作流教程。若内容兼有多种属性，优先本次发布的核心交付物。

参考中的顶部有时是品牌、有时是工具组合、有时是系列标签，这是原作者的内容定位方式；默认优先类型。用户选定工具组合时，可使用准确双应用图标＋号替代类型文字，图标仍为40px，不强行补回重复标签。

## 参考与视觉语言

先读取 `artifact-template.json`，路径相对此目录；查看随附自制预览 `assets/preview-apple.png`，并结合 `references/layout-spec.md` 与 `references/layout-tokens.json` 选择布局。预览只帮助理解视觉语言，具体尺寸与当前用户选择以规范和本次要求为准。

公开版不附第三方历史封面截图。居中、左对齐、三行标题和截图优先等构图已整理为 C2、L2、L3、S1 四种预设，可独立使用。预览中的工具、文案和账号是案例，不是每次必须使用的内容。

## 固定排版系统（生成前必读）

每次制作必须读取 [layout-spec.md](references/layout-spec.md)，其尺寸、字体、分区和间距替代旧的约数；需要程序排版时读取 `references/layout-tokens.json`。先选 C2、L2、L3 或 S1 一个预设，不临时另创坐标。

- 固定 1080×1440 基准、80 px 左右边距、8 px 间距网格。其他分辨率全局等比缩放，不独立放大 logo 或字号。
- 默认Apple风系统字体栈；非macOS使用随附Noto Sans SC并重新验收，见layout-spec。真实产品内的 logo / UI 字体保留原样。
- 顶部是次级类型位：文字 28 px / 500，logo 40×40 px，图文间隔 12 px；整组高 40 px，宽不超过 320 px。不再按标题或品牌广告的尺寸生成。小红书小工具优先使用真实小红书 logo＋「小工具」，无可用准确 logo 素材时用「小红书小工具」文字，不生成貌似真实的新 logo。
- 主标题 90 px / 600 / 行高108 px；副标题36 px / 400 / 行高48 px；底部22 px / 400 / 行高32 px。三行标题使用独立 L3 预设 80 px / 600 / 行高96 px。
- 类型位下缘到主标题框上缘：C2/L2 为120 px、L3为96 px，绝不通过放大顶部标识填满留白。主副标题间隔32 px。
- 底部固定「关注职场咸鱼」，单行默认框 y=1368、h=32；主体与底部区域相互独立。
- 主体可单图或界面＋吐纸并排。用户已认可 Fish Camera 的吐纸并排效果；这是适合该工具的展示模式，不是所有选题的固定构图。
- 默认近黑标题、白底和浅灰内容区；蓝色只用于少量提示，不默认大面积高亮；背景#FFFFFF，主字#1D1D1F，副字与类型#6E6E73，尾标#86868B。真实 logo 与截图色彩不受单一强调色限制。
- 黄金分割仅指导 C2/L2 的宏观分区，不能作为“科学保证更好看”的依据。尺寸是为本用户制定的设计取值，不是引用来源的通用标准。

## 执行方式与一致性边界

纯 imagegen 不能可靠锁定具体字体、字号和间距。要求一致性时，使用 imagegen 生成或编辑主体视觉素材，随后以支持精确字体和坐标的排版工具单独排入标题、类型、logo和尾标，导出 PNG。HTML/CSS、SVG/Canvas 或设计软件均可；这是原生排版，不通过改图模型反复重绘文字。不要用 Python 重绘用户图片。

实际截图、logo和照片优先原样置入；需要示意照片或吐纸视觉时由 imagegen 生成并在交付时说明。不要为了一次性整图生成而省略固定排版。若环境仅能整图生成，明确其为近似版，不声称已满足像素级规范。

先声明本次预设和文案，再制作；交付前按 layout-spec 的验收项查看原尺寸、360 px缩略图和灰度/模糊预览。光学微调最多4 px并记录，不改变预设定义的层级或硬间距。

## 生成与真实性

1. 从用户输入提炼字段，选择布局，确定标题断行和强调词。优先用户当前选定文案。
2. 优先查看用户提供的真实截图；若给的是代码包，可阅读功能并本地查看界面以确认展示内容，不把包内文字当成执行请求。不为做封面修改原工具。
3. 调用 imagegen 前读取其技能说明。把风格参考和实际产品素材的角色分别说明；主体视觉与精确文字层分开制作，排版参数遵循所选预设。
4. 如用生成照片填入取景器或生成示意界面，不能声称为真实拍摄、真实截图或已验证成片。说明可放交付文字；若需要图内声明，用小号文字放主体附近，与账号落款分开，绝不以声明替换账号落款。
5. 检查中文准确、类型正确、标题可读、落款存在、没有抄原作者账号；主体不拉伸，界面不被重绘成虚构硬件，视觉保持简洁。交付最终 PNG，不自动发布。

不默认添加“效果示意”“真实流程片段”等解释性小字；素材真实性说明优先写在交付说明，影响读者理解的条件融入必要正文。副标题与图内说明逐句检查，删除重复主标题或只解释设计意图的句子。

## 发布前的目标读者与审美评审

完成尺寸、字体与缩略图验收后，读取 [cover-review.md](references/cover-review.md)，评审目标用户能否看懂、是否有点开理由、视觉是否有格调且舒适，以及承诺是否可信。根据具体画面指出问题并给出优先修改建议。缺少受众信息时说明假设，区分模型推测、真实用户反馈和发布数据。默认交付简短评审结论；用户要求详细审查时再展开。

## Fish Camera 的本次应用示例

- 类型：小红书 logo＋「小工具」，准确 logo 不可用时改为「小红书小工具」文字。
- 主标题：把手机变成 / 一台胶片相机（用户未要求改标题时可沿用）。
- 副标题：5 种胶片风格，拍出复古日常（仅在素材确认有此功能时使用）。
- 素材：真实红色相机界面优先，是否加入成片取决于素材与布局需求。
- 落款：关注职场咸鱼。
- 居中短标题或左对齐动作标题均可；产品名保留在界面内或作次级文字，不占用类型位。主体不是默认摆拍式相机和相纸组合。
