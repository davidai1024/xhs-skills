# 标题：从真实内容中选出值得看的事

用于本人的发布标题与封面文字。只要标题就不生图；直接要封面时内部选定标题后继续成图，不默认把选择交给用户。用户已确定的文字优先保留。

先执行 [SKILL.md 的标题分析与创作主流程](../SKILL.md#标题分析与创作主流程)：理解素材 → 判定任务与初选方法 → 读取相关方法与案例并确认选择 → 写作 → 校验 → 修正与交付。本文提供措辞、事实与筛选的细则，不替代入口中的判定步骤。

当前依据为[5876条全量语义研究](title-research.md)。按已判定的类别读[12类方法与原作](title-method-library.md)，按目标平台读[账号与平台选择](title-account-platform.md)。需要可复制输出时用 `../assets/title-templates/` 的选题卡、交付模板与分支模板库。需要更多案例时先查本包的多案例详解及既有研究参考；完整5876条原文未随公开包分发，只有获得用户提供的数据后才能检索全库。研究口径见 title-research.md。


## 先确定这条内容是什么

从用户素材确定：谁做的、已经做成或验证了什么、实际会展示什么、观众关心什么、哪些条件或结果尚未得到支持。用户明确是作者时才用“我做了”；不能因上传了项目文件就自动断定开发归属。团队与个人按事实区分。

先判断此次发布是作品展示、产品上手、实验、教程、幕后、纪实、公告还是其他体裁。同一项目可以有不同内容：发布小游戏、展示操作更新、讲开发过程，标题的承诺不能混在一起。文件名中的版本更新不是自动选题，也不能为了更像参考标题把纯演示变成挑战或测评。

信息足以支撑一个具体角度就继续。只有缺少决定性事实才问一个短问题；不能编造功能，也不能擅自把“已完成成果”改成“准备做什么”来凑标题。

## 先找观看理由，再选句式

从现有内容比较几个真正不同的看点，选一个最能被画面或内容兑现的：

| 内容 | 优先寻找的具体看点 | 原例方向 |
| --- | --- | --- |
| 工具、作品、游戏发布 | 做成的东西有何可见特点；替观众跨过什么门槛；作品里哪件事值得体验 | DY389 分镜AI、DY132 拍摄车；不能统一写成“我做了个工具” |
| 上手、评测、对比 | 一项变化是否有用；看似矛盾的取舍；具体人群的一次使用选择 | DY202 大重与强、DY524 亿像素却不能拍视频 |
| 实验、挑战 | 明确变量、条件或限制，加一个真的会给出答案的结果问题 | DY095 修复照片、XHS407 限定预算拍片 |
| 知识、教程 | 熟悉现象为什么发生；常见直觉对不对；具体问题怎样解决 | DY035 音画不同步、DY273 甩相纸、DY402 频闪 |
| 幕后、职业、探访 | 平时看不到的一个环节；普通对象背后的异常规模或操作 | XHS004 洗飞机、DY112 F1换胎、XHS171 贵重快递 |
| 纪实、旅行、视觉作品 | 独特的到达、观察、拍到或完成；画面本身足够强时可克制陈述 | XHS428 蒸汽火车、DY056 得克萨斯、XHS400 荧光森林 |
| 社区、系列、公告、声明 | 本期具体对象与必要信息；是否依赖已有粉丝关系 | XHS282 旅行第3期、XHS153 舆情；不强加悬念 |

题材不是句式指令。根据材料选择具体观看理由，而不是强制“收益／作者行动／问题”各写一句。不同候选应让观众期待看不同的事，不只是“我做了”“能不能”“太厉害了”的改写。

“功能名＋操作步骤”不自动是看点，但具体操作本身有反常之处、能解释原理或是本次演示重点时，可以成为主标题。“我做了个……”是归属，不是自动吸引力。氛围句、情绪词和版本号都不替代作品自身的内容。

## 写出原语料中的具体与口语感

- **尽早落到实体。** 优先物件、场景、人物、动作：一张纸、一个旋钮、房间、换胎、打开、送去、拍到。不要把具体事实抽象成“全新体验、效率升级、创作赋能”。
- **选一个值得追问的细节。** 价钱、数量、时间、地点有解释作用才写；不用多个数字堆冲击力。读者应知道这个细节为什么出现在句子里。
- **信息顺序服务疑问。** 可以先给事实再追问价值，也可以先给门槛再揭示作品，或直接宣布一个完成的行动。一句成立就不硬加第二拍。
- **用自然口语和有力动词。** “能干啥、谁在送、怎么拍、到底在哪”适用于相应语境；不要每句都“竟然、彻底、震惊、我悟了”。保留自然停顿，不把标题写成论文摘要或产品说明书。
- **允许冷静与幽默。** “去了一趟……”依赖作品画面与受众关系；“我和设备谁先挂”是特定体验下的调侃。可学习说话方式，不可移植未发生的经历或损坏结论。
- **留结果，不藏对象。** 原例中有只说“这”“它”的标题，但往往依赖封面、剧情或熟悉作者的观众。面向陌生人的新作品，至少让标题或封面明确对象；不要仅为悬念把题材藏掉。
- **不机械复制词面。** 迁移“普通物件与异常成本”的关系，不把任何产品都改成“这个XX，为什么卖XX”。原文中的免费、首次、最强、预算、身份、人数都不是可复用事实。

## 事实与内容承诺

标题可以提出内容正在检验的问题，不必先公布结论；但疑问句不能夹带无依据的前提。“真的更快吗”需要比较内容，“这么快还免费？”已暗示速度与免费，两者都要有证据。

区分：做出原型／可用／已发布；一次上手／长期体验；可观察差别／已证明原因；作者感受／客观结论。保留会改变读者预期的限制，不要求把全部测试条件塞进标题。未经提供的“上瘾、治愈、零误差、省时百分比、全兼容、只花一天、全网首个”不写成事实。

若用户只提供版本变化，先看变化能兑现什么内容，不能自行声称“手感更好”“再也不误触”。看到功能存在，不等于已经测得用户效果。检查限定词是否被悄悄扩大，例如“复杂双栏需放大”不能改为“所有双栏都难读”；不能仅因素材没有说去过森林，就断言“没去过森林”。所有候选都要过事实检查，不只检查推荐稿。

## 把核对记录留在内部，让成稿像一句话

事实表不是标题稿。不要把作者身份、参与者、拍摄范围、动作步骤和限制逐项串完。先选一句能自然说出口的话，只留下会改变观看理由或内容承诺的背景；其余交给正文。保留限制不等于把标题写成长篇免责声明。

优先让动作直接发生：“师傅拆开了什么”，通常比“展示师傅进行拆解的操作过程”自然。看到“记录……的片段”“拍下……的步骤”“展示……的过程”，检查是否只是名词化的工作日志；若用户本就要日志或过程说明则可保留。不要一律在末尾追加“给你看”“我做了个”“完整演示”，除非它增加真实信息。

成稿后反向核对每个候选和封面：谁做、对什么做、在哪、何时、与谁比较、结果是否已知。压缩不能把动作移到另一个对象，不能把单个场景扩大成普遍规律，也不能把“没有使用某素材”写成“没有经历某件事”。“我／我们”也属于事实，镜头前的旁观、试用或访问不自动变成制作和团队行动。

封面与发布标题可以互补，但封面自身不能改写实验条件、作者身份或关键限制。标题里正确的限定不能补救封面里的错误。若保留限定会使封面太挤，换一个仍然准确的重点，不直接删掉限定。

## 发布标题、封面大字、人物动作

先用一句话确定三者共同承诺什么，再压缩：
- 发布标题交代对象和看点，脱离封面也尽量能理解。
- 封面大字保留同一个值得看的重点，不在压缩时只剩项目名或使用说明。短句可以由画面补足对象；不硬性禁止两处重复关键词。
- 人物动作与真实成果证明看点。不要因某个姿势容易画，就倒推一个平淡标题；也不要为了标题制造素材中没有的产品界面或成果。

若用户只要发布标题，不额外输出封面文案。用户要成套方案时才展示完整组合；只要封面时可内部拟定发布角度，不把未请求的文案清单塞给用户。

## 生成、比较与修正

素材足够时默认给3个候选并推荐1个，用户明确指定数量时从其要求。同一强方向可给侧重或语气确有区别的表达备选，并说明共享角度；不编事实凑数。决定性信息不足时先澄清。只处理标题与用户需要的封面字，不执行成图。

用以下问题筛选，不报“爆款分数”或伪精确预测：
1. **承诺**：读者点开想看到什么，已有内容真的提供吗？
2. **特异性**：是否保留这个内容自己的细节，换成其他项目后是否仍几乎通用？
3. **表达**：有没有具体对象和自然动作，是否为了模仿而生硬倒装、堆问号或添营销词？
4. **适配**：语气是否适合这类内容和受众？声明不娱乐化，纪录片不强行教程化，作品不冒充评测。
5. **组合**：封面压缩后看点还在吗，人物和画面能支持吗？

推荐时用一句话说明选中了哪个真实看点即可。不因同一句套上“我做了”或把句号换问号就宣称改善了。用户认为平淡时先重选角度，再修改措辞；不要只加情绪词。

风格目标是接近参考账号可观察到的选题表达和节奏，不是仿冒身份或保证点击效果。原账号的传播还取决于作品、封面、受众与账号关系。
