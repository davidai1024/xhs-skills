# 选看点与复选

## 先定这篇交付什么

用一句口头话说清对象、实际动作和读者能看到的结果。产品可能交付一次上手、对比或买旧款的理由，创作幕后可能交付一个具体项目的制作过程，公告可能交付已经开放的入口。优先找片首提出并在正片兑现的事。只在转写里找到的专名、数值或原话，要回原声、画面或官方字幕核对。

| 素材给了什么 | 优先拿来比较的写法 |
| --- | --- |
| 事件已经发生，动作本身就够具体 | 直接报谁做了什么。起因、过程和后续可以留给正片。 |
| 两个真实事实放在一起有反差 | 先给读者能理解的身份、费用、时间或尺度，再给它引出的动作或具体问题。实际投入与成品是一组，配置、报价和实付各按自己的口径。 |
| 观众真正需要一个答案 | 先确定是在问原因、办法、体验、选哪一个，还是最后拍到了什么。把能想象的前提说清，给正片留出答案空间。 |
| 人物、作品或机型承担观看理由 | 优先写熟悉且能核到的名字。标题中的称呼要让读者认出是谁、哪一部或哪一台。片中只用于解释的次要对象通常留在正文。 |
| 作品、样片或资源已明确开放 | 比较一条能同时说明是什么、观众可以怎样取得或使用的稿。免费、下载、许可和适用范围各自核实。 |
| 帖子展示一场实际做过的对比评测 | 题面先点出两边在比什么，再给观众一个具体选择。评测方式本身有看点时，写清真实的选项和玩法。网站和制作过程可以在正文展示。 |
| 剧情短片或表演靠揭晓推进 | 从实拍到的动作、道具和人物关系起笔，留住揭晓。把虚构设定限定在表演或角色视角，实际产品发布和性能需要各自有证据。 |

## 比候选时只问会影响选稿的事

1. 先比较看点。读者会等完全不同的答案时，确认哪个答案和实际交付更贴近。一个真实的亮点也要能代表承诺的内容范围。
2. 再比较句子用途与顺序。直说已知结果、询问未知结果、用已知前提引出下一截，给读者的预期不同。每截做一件事，短题能撑住就停。问号、感叹号和停顿跟着原话的作用与强度走。
3. 最后检查会改变期待的修饰。人物身份、明确金额或完整型号一旦拿掉就失去反差时保留。具体结果留给正片时，题面仍要让人知道该等什么。精确栏目、版本、价格和年份有材料才写。

遇到拿不准的地方，从[历史对照](cases.md)选最像的 1 到 2 个解释取舍。默认在最终答复里只给可用标题和简短推荐理由。
